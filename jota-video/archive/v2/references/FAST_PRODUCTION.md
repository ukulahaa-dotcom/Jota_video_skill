# JOTA FAST PRODUCTION — Artistly → VideoExpress (v2.2, verified long-take continuity, 2026-10-24)

**Goal:** make operating JOTA reliably faster by removing unnecessary click-by-click overhead and doing the **main quality checks on P1/P2/P3 prompts BEFORE spending credits**. Read [`FILMMAKER_PREGEN_QC.md`](FILMMAKER_PREGEN_QC.md), [`CHARACTER_CONSISTENCY.md`](CHARACTER_CONSISTENCY.md), and all three prompt-director modules. Do not weaken user mode choice, provider source, media rights, privacy or final-film QA. The success metric is completed **accepted** clips per session, not tool calls, long prompts or superficial “PASS” counts. This **replaces the slow interaction sequence**, not quality/security/release requirements.

**Creative mode first:** require explicit owner `JOTA_1` or `JOTA_2` on EVERY new independent video per [`CREATIVE_MODES.md`](CREATIVE_MODES.md). Do not infer from film style; `MODE_SELECTION_PENDING` stops jobs. This is distinct from FULL AUTOMATION execution (the selected goal in either mode). The `FAST` strategy does not reduce quality gates; only the applicable face/music/lipsync checks change.

**Mode selector — FULL AUTOMATION remains the owner-selected goal.** Use [`FULL_AUTOMATION.md`](FULL_AUTOMATION.md); this file optimizes its execution sequence and is not permission to switch modes unilaterally.
- **FAST (execution strategy inside FULL AUTOMATION):** one story plan; prepare multiple independent Artistly image prompts; group provider actions; select approved stills; native VideoExpress import and generation in small provider-supported groups; inspect QC at the required acceptance boundaries; edit/export natively; maintain small event-based ledger. This is **semi-automated UI execution**, not a deployed API scheduler.
- **MANUAL ASSIST (explicit owner opt-in only):** never make the user perform production just because remote clicks are slower. First group supported app actions, preserve provider job identities and investigate UI inefficiency. If the automated execution path is genuinely blocked, give the blocker and request the decision, not an unrequested manual handoff.
- **DEEP QA / DIAGNOSE:** only for failed scenes, uncertain critical policy boundaries, or **mandatory final review**. Do not spend production time running slow diagnostic tooling against every already-safe intermediate status.
- **PLAN/UPDATE:** only repo documentation, workflow/settings, no new provider job, no new credits; immediately stop/pause active production when user pivots to workflow improvement.

## Fastest long-take lane — optimize meaningful shots, not prompt count
Use [`CONTINUOUS_SHOT_FIRST_LAST.md`](CONTINUOUS_SHOT_FIRST_LAST.md). For 60s films prefer **fewer purposeful camera cuts** and up-to-10s source segments **where an actual VideoExpress tool can deliver them**. Longer intended one-shot movements use `actual last native video frame → exact next first image` and a reachable last-frame target in native First/Last mode; do not rebuild each segment in Artistly from scratch or reset the camera. Do scene/take blocking and target last-pose cards once, then only verify the **join's end/start ~0.5s** after each new generated segment, and perform a full final take watch/listen. Do not blindly force 10s (JOTA native lipsync request 6s yielded 5.042s actual), duplicate images/renders, run redundant QC on all previous shots or mass regenerate failing sequences. For speaking JOTA2, audio-coupled lipsync pilot still must PASS before batching; never optimize away linguistic QA. No false promise of automatically invisible joins or unauthorized media job.

## Lean bounded production lane

### A. Once per episode (not once per click)
1. Check expected Artistly/VideoExpress authenticated account, workspace, private setting, current user generation authorization, credit/billing limits, and 16:9/9:16 format. Avoid secret/token access.
2. **LOCK ARTISTLY reference characters/world first** (K1, C1, multi-character slots when verified) and write the full screenplay/actor dialogue timeline and compact shot cards for *all* scenes first: `SCxx | duration | speaker | character/world locks | approved still version | short physical motion | camera/axis | audio cue`. Check speaking tone, no narrator if requested; faceless/no-lip-sync/no-music.
3. Compile **THREE film-director prompts per shot** (P1 detailed Artistly still, P2 physical VideoExpress motion, P3 named actor dialogue/lip-sync) with necessary reference IDs. Avoid 2,000–4,000-character repeated *boilerplate*: keep detailed scene-specific staging while short stable bible/reference locks are reused. Put immutable continuity in a short reusable style lock plus only scene-delta details, but **repeat the handful of critical look/faceless/axis rules in each submitted prompt**. A prompt must never depend on another chat message for essential constraints.
4. Run a single master checklist for episode safety/rights, output ratio and naming. Do not repeat UI capability reconnaissance on every shot unless UI changes.

### B. Artistly batch images
1. Group requested scenes by **shared character/world setup**. Where authenticated UI supports quantity/batch, create a *bounded* batch of draft start-images (e.g. 2–4), using **16:9** for landscape, `Private`, dedicated **CANDIDATES** folder, and recorded prompt/scene-version links. **Confirm how quantity works before a paid batch; do not assume it accepts different prompts in one request.**
2. A quick first-pass gallery scan classifies `CANDIDATE`, `REJECT`, `REVIEW`. Inspect **every accepted still at full size**, especially animal faces, reflections, anatomy, camera geography and style. A cropped/frontal face is a FAIL even if the scene is pretty.
3. Only `APPROVED` images proceed. Move via UI only when the exact image is selected; capture the source image ID at the moment it is approved. Reject and correct just the bad scene; do not regenerate accepted stills.
4. For faces, **fix framing/occlusion**, not merely append more “no eyes” negatives. Maintain characters physically present where the dialogue scene needs them; environment-only establishing shots are an intentional occasional filmmaking choice, not a substitute for all acting.

### C. VideoExpress group import and render
1. **Preflight twice, once at editor and once at generator**: native landscape 16:9, `Image Type: 2D`; `Share in public gallery: OFF`, image/video prompt enhancer: OFF; mouth/lipsync/narrator: OFF unless narrator-led explicit project; `Video Only (No Sound): ON` for dialogue added later; verified manual length corresponding to shot and provider availability.
2. Import approved Artistly stills through **Import Media → Import from Artistly**. Compare the exact image; capture VideoExpress import ID and Artistly source ID in manifest. Never choose the top/latest gallery tile by sort order.
3. Prepare P2 `SCxx-VID-vN` and P3 `SCxx-DIA-vN` prompts first and PASS their specific gate **before** paid video/voice jobs. Submit **a bounded set of independent clips** only if current UI actually supports it and credit limits permit. Otherwise submit sequentially without waiting on each individual render before preparing the next. Do **not** retry pending jobs, double-charge, or submit without source identity.
4. Check the queue/status **at meaningful transitions** (job accepted, completed, failed), **not in a rapid polling loop** or via repeated opens/toggles. A provider job acceptance is `SUBMITTED`; a media asset is `RENDERED`; visual quality is `NOT ACCEPTED` until QC.
5. Keep all identifiers in an event/scene ledger: `SCxx IMG-vN → Artistly design ID → VE imported image ID → VID-vN → VE job UUID → VE media ID`. Update GitHub state **at major milestones or on pause**, not after every browser click; avoid rewriting entire JSON repeatedly.

### D. Thorough prompt QC early, lean rendered checks, full final film QC
- **After `P1_IMAGE_READY` and image generation:** quickly inspect the exact full-sized still. Wrong face/ratio/composition → reject before video cost.
- **After `P2_MOTION_READY` and a rendered clip:** use a **short real playback** to see actual beginning/middle/end acting, reference identity, video geometry and obvious audio anomalies. Frame contact sheet is optional diagnostic, not default. Record `RENDERED_QUICK_REVIEW` (not final `QA_ACCEPTED`); a well-written prompt or sample stills cannot guarantee correctness.
- **Before any final export or owner review:** a mandatory **complete assembled-film visual/audio playback** checks continuity, selected-mode facial quality (comprehensive faceless inspection for JOTA 1 where necessary), scene acting, P3 dialogue/lip-sync, music/ambience mix and rights, native VideoExpress provenance and private export. Deep per-frame investigation occurs for specific real defects, not every JOTA 2 intermediate clip. If automated all-frame inspection is too slow, defer final acceptance to a scheduled active review step or request owner review; do not downgrade requirements.
- **On first failure:** classify the exact root cause, edit just affected image/motion prompt and rerender bounded attempt if authorized. Never redo every scene.
- **Sound by mode:** river/wind/leaves/birds/footfalls allowed in both; `JOTA_1` has no music/no lipsync; `JOTA_2` may include rights-cleared music and supported requested lip-sync. Dialogue-only films do not become narration films in either mode.

## Fast UX/operator guard (avoid overengineering)

- At most **one authenticated UI setup pass per provider session**, one import mapping confirmation per unique still, one submission confirmation per clip. Further UI probing only for real errors/status mismatch.
- Prefer a **single bundled read** of the needed visible controls before acting; avoid chains of probing title, element HTML, enable flags, and click result when the control is already known.
- Prefer first-party supported app workflow buttons, Artistly native batch/bulk functions, VideoExpress existing media folders/queue and saved projects. **No undocumented internal API**, browser token harvesting or security bypass.
- Avoid unnecessary repeat Artistly/VideoExpress navigation. Keep each in its own verified tab with the current project and folder active.
- Avoid forced exports/downloads/collage/24fps frame extraction on every intermediate step. The full QC obligations still apply **before acceptance**; choose an efficient viewer/workflow for review.
- If a basic provider operation needs excessive agent interactions, **optimize the Chrome UI adapter or mark AUTOMATION_BLOCKED with proof**. Never switch to MANUAL ASSIST without explicit owner opt-in. Do not exaggerate automation gains.
- If user asks to **stop/pause**, stop new provider submissions immediately; preserve only the minimal known submitted job IDs and asset IDs; no speculative job cancellation or deletion. Repo/workflow edits can proceed independently.

## Measurable adoption criteria

Track per pilot *without inventing durations*: provider generate/queue time; agent UI setup/actions; number of provider jobs; scene count; rejected attempts; exact clip provenance; QA acceptances; elapsed time only when real timestamps available. Pilot succeeds when:
- all requested scenes can be staged with fewer agent UI interactions than the previous click-by-click method using supported app controls and no unapproved manual operator handoff;
- approved 16:9 Artistly stills map 1:1 to imported VideoExpress images and native clips without mix-ups;
- no extra VideoExpress generation is triggered for a source still failure, and no duplicate job is submitted;
- selected-mode face/audio policy (`JOTA_1` faceless/no music/no lip-sync OR `JOTA_2` expressive/licensed music), privacy/rights, character identity and native VideoExpress final-export checks remain enforceable.

**No mode permits bypassing technical scene QC, original content licensing or privacy.** In JOTA 2 full-face and music checks are **quality/rights** controls, not JOTA 1 faceless prohibitions. Do not promise a fixed speed-up, throughput, parallel jobs, bulk APIs or unattended operation without measured evidence.
