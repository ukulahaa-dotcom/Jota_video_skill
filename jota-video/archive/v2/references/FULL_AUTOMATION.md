## Full-auto decision and recovery rules

1. At the **start of each user request**, respect the current task: if user says update skill/plan only, STOP new provider jobs; if user explicitly orders continue making the film, resume from confirmed scene IDs and authorized provider state. Do not ask the owner to perform basic known UI actions.
2. **One-time provider preflight per active session:** expected app/account/project identity, generator/editor ratio separately (both can diverge), private/gallery OFF, original 2D, audio/lipsync disabled for motion, current cost budget/limits; all important controls and target folder set. Do not tamper with authentication, browser settings, cookies or provider undocumented API endpoints.
3. **Compact prompt compilation:** scene-specific positive physical staging and real actions are more valuable than a repeated wall of negative words. Always carry aspect, style, exact subject/crop, **selected-mode face/music/lip-sync policy**, fixed geography, no unrequested text, and source/license constraints. Voice/dialogue stays in a **separate cue**, never the visual generation prompt.
4. **Batch stages, not blind bulk actions.** Prepare scene prompts together. Use Artistly/VExpress supported UI quantities/queues only when actual UI proves their semantics and billing limits. Distinct prompts cannot be silently conflated with one multi-image same-prompt job. Only safe, bounded concurrency; exact `SCxx → IMG → Artistly ID → imported VE ID → VID job UUID → VE clip ID`.
5. **QC two tier:** reject unusable Artistly stills early (full-size), run cheap rendered-video triage promptly, then whole-clip visual/audio QA before `QA_ACCEPTED`; a contact sheet alone never guarantees all-frame absence of face features. Full native final cut QA remains mandatory.
6. **Meaningful checkpoint writes:** on source still approval, import verified, video job accepted, clip ready, QA accept/reject, project save and final private export. Avoid one GitHub write per browser click; update current `RUN_STATE.json`/manifest at session checkpoints.
7. **No duplicate/cost-wasting attempts:** if a provider job is in-flight/unknown, lookup matching job/library evidence before any retry. If the same defect happens twice, investigate one-variable cause rather than repeated blind renders. Do not build unapproved integrations to bypass the provider.
8. **Failure/slowdown:** if a UI click breaks, try one bounded supported recovery (re-read UI state, correct preflight field, reopen the approved provider panel); report `AUTOMATION_BLOCKED` if essential control/access is truly unavailable. Do **not** automatically switch to MANUAL ASSIST; ask one material choice only if necessary (consent/cost/credential/platform limitation).
9. **Explicit owner decisions required:** paid/provisioning action beyond existing quota, destructive/migration, security or credential changes, unauthorized remote runner setup, public release, content deviations, incompatible rollback. Maintain private-by-default in both creative modes; only `JOTA_1` forbids music, while `JOTA_2` permits requested licensed music.
10. **Evidence standard:** `FULL_AUTO_SELECTED` = intention, `UI_OPERATOR_VERIFIED` = current Chrome control, `SOURCE_STILL_APPROVED`/ `VE_IMPORT_VERIFIED`/ `VIDEO_JOB_SUBMITTED`/ `VE_CLIP_RENDERED`/ `SCENE_QA_ACCEPTED`/ `NATIVE_EXPORT_VERIFIED` represent separately verified milestones. **Do not confuse full automation selection with completed background autonomy or a finished 60-second movie.**
