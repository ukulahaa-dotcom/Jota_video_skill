## What Paul is actually teaching — source-grounded paraphrases
1. **Don't stop at copy/paste:** the public one-shot system prompts are intentionally opinionated, preset-heavy shortcuts. Build a customizable playbook to change cast, voice, style, framing, length and use case.
2. **GitHub as a persistent hierarchy:** README, system instructions, examples, evaluation checklists and specialized submodules make a reusable library. The work should not be stranded in ephemeral chat windows. GitHub ownership and connectivity allow revising the workflow over time.
3. **Examples teach visual intention:** attach or describe permitted inspirational reference examples (YouTube/Instagram footage) and analyze their editing, style, ambience and cinematography before developing an original interpretation. A reference URL does NOT give rights to copy visual assets or characters.
4. **Evals are reusable corrections:** when repeated errors occur, write a measurable test/check so an agent will catch the failure next time. Paul uses missed lip-sync as an example; for JOTA the same concept becomes a strict **no-lip-sync, no-facial-features** compliance test.
5. **Different formats need separate playbooks:** TikTok-style vertical framing cannot safely be achieved by changing one `16:9` field to `9:16`; layout, subject placement, pacing and platform conventions must be reconsidered. JOTA will have separate Shorts and landscape-long-form presets.
6. **AI agents coordinate specialized operations:** an agent can plan scripts, prompts and production, operate connected tools or an isolated browser, and reconcile output into the timeline. Paul demonstrates different AI frontends and notes that they vary in timeline automation capabilities.
7. **Compose workflow modules:** historical/documentary or spokesperson methods can be reworked and combined. Paul advocates creating your own branded system, not making thousands of indistinguishable copycat videos.
8. **Keep extending and versioning:** adjust failures, voice preferences, camera control, narrator/scene rules and examples, then store the improved version in the workflow library.
